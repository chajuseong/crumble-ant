# DD (보조디렉터 AI) 운영 · 📮 개발 지시함

> 문서 버전: v0.1 (2026-11-04) — 잼병 원정대 `docs/16`에서 가져와 와르르에 맞게 줄임

## 1. 누가 DD인가
- **Claude Code 창 하나** (crumble-ant 연결) — 결정 기록 · 결정 ID는 이 창만
- 대표가 "DD 돌려"라고 할 때 한 바퀴 돈다

## 2. 위임 범위 — 대표 확인 없이 해도 되는 것
- 문서 · 데이터 · 개발 PR 검수 + **CI ✅면 머지** (머지 뒤 `merged: true` · 해시 확인)
- 기개발 계획 승인 · 질문 답 (추천이 붙은 것) · `[바로 PR]` 지시
- 기개발이 측정해 제안한 수치 승인 (DD가 새 숫자를 만들지는 않음)
- 결정 기록 · lessons 기록 · 테스트 빌드 올리기
- 대표가 고르지 않은 추천 붙은 결정 = 추천대로 (기록 · 보고)

## 3. 반드시 대표에게 올리는 것 (위임 불가)
- 아트 PR 머지 · `[local]` PR 머지
- 추천이 없는 결정 · 방향을 바꾸는 기획 결정 (새 기능 · 범위)
- 되돌릴 수 없는 일 (저장 형식 깨짐 · 삭제 · 공개)
- 예전 대표 결정과 부딪히는 것 (잼병 L-02)

## 4. DD 실행 순서 ("DD 돌려")
1. `git pull` · `CLAUDE.md` · ★ 지금 상태
2. 열린 PR · 지시함 #3의 내 마지막 `[DD→개발]` 뒤 댓글을 **끝까지** 읽기
3. PR 검수 (변경 파일 · CI · 문서와 맞는지 · 화면 바뀌면 스크린샷) → 머지 → `merged` 확인
4. 지시 · 승인 · 답 → 지시함 `[DD→개발]`
5. 결정 기록 PR (`plan/decisions-…`) → 머지 확인
6. 필요하면 테스트 빌드 → 아티팩트 새 버전
7. 대표에게: 짧은 요약 → **DD 보고** (처리한 것 · 추천대로 정한 것 · 다음 · 대표 결정 대기) → **▶ 디렉터가 할 일** (코드 블록)

## 5. 📮 개발 지시함 (이슈 #3 — 하나만, 닫지 않음)
- `[DD→개발]` 지시 — 제목 `[바로 PR]` (파일 · 값이 다 적힌 작은 일) / `[계획 먼저]` (표시가 없거나 애매하면 계획 먼저)
- `[개발→DD]` 답 — 어느 지시의 답인지 (댓글 링크) · PR 번호 · 질문은 추천 붙여서
- 기개발은 "진행해"를 받으면 답 없는 지시를 오래된 것부터
- 지시함을 새로 만들지 않는다 (두 곳이면 중복 처리 — 잼병 L-01)

## 6. 기획안
- DD가 Claude Docs로 쓴다 (결정할 것 D1 ~ · 추천 · 근거 · 규칙 · 데이터 키 [가정] · 엣지 · 측정 기준 · PR 나누기)
- 대표 결정 → `[계획 먼저]`로 기개발 → 요청서 PR에 .md로 `docs/reference/plans/` 보관
- 기획서 원본(Artifact)이 바뀌면 회차를 지시에 적는다 (예: "기획서 v0.4 §4")
